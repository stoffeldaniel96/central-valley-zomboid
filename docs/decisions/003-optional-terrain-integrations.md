# ADR-003: Standalone map and optional terrain integrations
Status: accepted product requirement; implementation pending (user clarification 2026-11-26).

The mapping toolchain and base playable map must build and operate without Viewpoint or Better Terrain, directly or transitively (including ZombieBuddy solely for those integrations). Full Viewpoint compatibility remains an acceptance requirement, not a player installation requirement. Research into Better Terrain does not approve a mandatory dependency, a fork, or copying its implementation.

Canonical signed elevations, planar foundations, surfaces, independent decks/subsurface spaces, material/mechanical semantics and stable assets remain renderer-independent. Third-party formats are adapter outputs, never authoritative inputs. Model-first volumetric asset generation continues per asset-contract.md.

## Runtime configurations
- Native base: no Viewpoint or Better Terrain. Use native slopes, levels and reusable assets first; a project-owned runtime extension is only justified by demonstrated gaps and must work without those third-party mods.
- Viewpoint alone: identical base geography with compatible model/texture/state bindings; Better Terrain not required.
- Viewpoint + Better Terrain: optional adapter if a supported, version-compatible provider or data format is available. One physical elevation authority, no double-applied relief, no modifying upstream installation or silent fallback to standard Kentucky terrain. Disable unsupported integration explicitly, preserving base behavior.

## Acceptance
Test actual Turlock benchmarks in native-only, Viewpoint-only and supported combined configurations, on pinned builds and fresh saves. Compare slopes, negative Z, foundations, access, deck clearance, collisions and traversal. Visual fidelity may differ; mechanically meaningful geography must remain functional. Document measurable backend differences; do not silently flatten important features. Flat control is a format-loading experiment, not terrain parity. Native arbitrary slope support, Better Terrain custom provider and multiplayer behavior are unverified. No new dependency approved.

## 2026-11-27 clarification: maintainable fidelity, not native at any cost
User-approved direction: own canonical geography and compiler; select runtime implementations by fidelity, supportability, ecosystem compatibility and cost of maintenance. Viewpoint compatibility is mandatory out of the box on supported version combinations; neither Viewpoint nor Better Terrain is a required player installation. Better Terrain incompatibility without an explicit compatibility adapter is acceptable. Do not silently combine elevation authorities. ZombieBuddy is accepted for the experimental runtime adapter rather than a bespoke Java agent; production dependency selection remains evidence-gated. Keep the no-Viewpoint/no-Better-Terrain base product functional, but do not conflate this with a requirement to reproduce useful mod infrastructure. No guarantee of arbitrary-mod compatibility; test and document conflicts.

Keep exact class-hash guards for probes only; production candidate should select by supported game/API version and behavioral capability checks, use public method/API contracts and scoped composable hooks, leave correct native results unchanged, decline unknown versions visibly, and provide a regression suite and migration path. Never bypass unrelated wall/stair/water collision. If native behavior becomes correct, retire that feature patch independently. Do not make unvalidated fallback flattening a playable release. Avoid global tileGeometry override. Test active-world scope, fresh JVM/save, disable/re-enable and client/server separately. No commitment to support every game patch immediately.

## Evidence and next gate
- https://steamcommunity.com/sharedfiles/filedetails/?id=3821216065 (Knox Real Terrain, Oct 16 2026): author reports replacing Better Terrain procedural elevations using 30m 3DEP data warped to Knox; load order/cache rebuild required; custom maps still unsupported per author comment. Workshop source folder reportedly included, not inspected; page also shows removal/incompatibility notice, availability uncertain. No reuse permission inferred. Obtain source only if accessible; evaluate exact injection point, license, lifecycle, units, cache and dependency burden. No fork or reliance approved.
- https://steamcommunity.com/sharedfiles/filedetails/?id=3815223174 (Better Terrain 0.3.24): targets 42.21, custom-map data and multiplayer not validated; internal Surface abstraction found earlier, no supported provider verified. Ask maintainer for documented custom provider, signed surfaces, stacked-level policy, coordinate/interpolation, cache and version contract. Do not copy code.
- https://docs.projectviewpoint.org/start/introduction/ and https://docs.projectviewpoint.org/api/view-state/: documented resource/model/service/hook APIs; coordinate scale sqrt(6) storey per square width; terrainHeight is read-only. API/samples MIT, not necessarily implementation. Docs say internal hooks can break each release and ZB mods are unmanaged by Viewpoint. Prefer supported resource bindings and verify actual installed versions; do not assume a terrain provider exists.
- https://projectzomboid.com/blog/news/2026/07/next-steps-2/: announced mapping tools and modding improvements, no specific promise of arbitrary slopes found in reviewed announcement.

Next experiment is renderer compatibility on the existing real B01 patch, not an expanded patch suite: check installed Viewpoint version/game support, baseline with existing map and ZB correction, register existing original model pack by supported interface, disable optional procedural relief for isolation. Compare same surface, player Z, lighting, seams and view modes; no duplicate offset. If unsupported build, pin compatible disposable environment rather than modify live installation. In parallel investigate Knox Real Terrain provider and upstream support. Only then choose whether to extend four-corner/edge logic or delegate to a replaceable terrain backend. Acceptance: signed elevations, connected nonplanar terrain, vehicles/zombies, interaction and construction, visibility/lighting, save/load, cross-chunk seams and Viewpoint parity. Preserve source data irrespective of outcome. Stop expanding owned runtime if correction requires broad coordinate remapping or multiple subsystems with no stable contract unless comparison demonstrates compelling advantage. All such thresholds qualitative pending evidence.
